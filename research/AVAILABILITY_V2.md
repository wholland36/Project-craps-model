# Availability v2: research contracts

This separate module does not change any frozen candidate, official model, Elo state, forecast, wager or canonical Sheet. It produces rating/workload burden units, never scoring points or claimed betting value.

`administrative_status(player_id, report, policy, cutoff)` requires a source-authenticated complete report, authenticated complete eligible roster, exact conference and season, covered conference game, applicable policy window, and publication/observation before the pregame cutoff. Only an authenticated policy explicitly defining omission as Available permits that derivation. Explicit statuses retain their administrative meaning. Available never establishes full workload. Missing feeds, uncovered games and uncertain roster coverage remain Unknown with flags. The caller must supply truthful source attestations: booleans are contracts, not an independent authentication service.

`allocate_replacements(losses, roster, cutoff)` requires verified identities, roles, workload and point-in-time rating iteration. Non-QB fallback uses the average of at most three strictly lower-rated eligible teammates, including one or two when fewer remain. Verified pregame actual replacement takes precedence, including a higher-rated replacement. All simultaneous losses and non-Available roster players are removed from the pool. The PRIMARY prior is independent for each injury: `primary_replacement_ids`, `primary_replacement_rating`, `primary_prior_resolved`, `primary_burden`. Earlier hypothetical allocations cannot change that requested mean. A separate depletion sensitivity scenario uses legacy `replacement_ids`, `replacement_rating`, `resolved`, `burden` fields: deterministic greedy allocation gives actual replacements priority, then higher-rated losses, reserving pools exclusively. This avoids double use in the sensitivity only and is intentionally conservative, not an optimizer or observed rotation. Do not substitute depletion fields for the primary prior. Shared real snaps require a later verified fractional-capacity extension. Exact positions only: no invented OL/defense snaps, cross-position roles or QB fallback. An unresolved actual replacement does not silently become a verified estimate. QB values remain unresolved without verified replacement evidence. Higher-rated replacements retain signed gaps for audit, with nonnegative loss burden clipped to zero.

`state_relative_burden(current_burden, embedded_burden, rate)` keeps an independent availability burden EWMA. The incremental feature is current minus embedded burden. The returned next state must be applied only after a completed observed game; it never alters Elo. The default .15 matches a score-update hypothesis, not a fitted causal effect. Unknown history stays unknown. `role_restoration` explicitly scales a return from its absent-role burden and must come from a pregame expected workload estimate; Available alone must not be passed as 1.0. Separate return restoration prevents an automatic equal-and-opposite full benefit.

Existing archive review found provider game-day stage records and retrospective player transitions, but the delivered metadata do not establish authenticated, complete eligible rosters and original report publication clocks for policy-based omission recovery. Consequently **zero recovered historical states are claimed**. All existing unresolved game inputs remain retained and unscored. Conference policy leads require exact current-policy authentication before populating these contracts.

Run `python -m pytest tests/test_availability_v2.py -q` from the checkout. Tests cover policy/time/roster boundaries, one/two/three backups, strict lower ratings, simultaneous absences, shared capacity, actual-first priority, future evidence rejection, QB identification and asymmetric return recursion. Integration should preserve these source receipts and flags and pre-register any coefficient fit on new data.

`build_identity_crosswalk` requires evidence-backed ESPN/EA/team-season keys and rejects duplicate ID or normalized-name identities within team-season. It performs no name fuzzing or implied verification. `known_unknown_coverage` retains unresolved denominators and explicit flags. `uncertain_scenarios` emits active/out burdens without inventing probabilities. `verified_ol_continuity` counts unchanged slots only from two complete pregame verified lineups; it does not invent snaps or scoring points. All verification booleans are caller attestations and cannot independently authenticate a source.
